- **Consecutive-failure error policy + generic retry helper (20260928)**: replaced the per-exception-class error routing with the two-level policy agreed with the user. The old mapping was incoherent with its own rationale — TimeoutError (the only case where NIS state is truly unknown, the macro may still be running) was "recoverable", while KeyError (macro returned, state partially known) aborted the grid — and it had a silent total-failure hole: an all-timeout run ended "Grid done: 0/N" with exit 0. New policy (documented in the pipeline module docstring, per user instruction to keep design notes in existing documents): (1) FOV level — any exception out of the stage move or `autofrap_loop_inner` fails only that FOV (the finally-cleanup normalizes the GUI state); the grid continues and aborts once `max_consecutive_failures` (new parameter, default 3, CLI `--max-consecutive-failures`) FOVs fail in a row — a repeated failure is systemic (disk full, NIS wedged, detector down); a completed FOV (even with zero cycles) resets the counter; a stage-move failure counts as an FOV failure (per user: the macro call already retries 3×). (2) Run level — new `AbortRunError` aborts immediately for pre-flight configuration/resource errors (invalid name, missing positions, run-dir collision, NIS not running, misconfigured survey template). Exception hierarchy: `RecoverableError`/`NonRecoverableError` deleted; the `AutofrapError` base is now raised directly for intentional FOV-level failures (detection wrap, missing survey/FRAP file, ROI id ≤ 0, bad detector output shape); the inner loop's TimeoutError/KeyError/OSError translation block is gone (plain try/finally with the best-effort cleanup). `setup_microscope`: template check moved out of the retried body (no more pointless retrying a misconfiguration), retry narrowed to (KeyError, OSError, TimeoutError, RuntimeError), final failure now raises `AbortRunError` — previously a raw NIS exception reached the CLI as an uncaught traceback. Recorded the timeout assumption as a design decision (module docstring, per user): all non-acquisition macros complete well within their 10–20 s windows, so a timeout is a genuine fault — no probe/settle-wait machinery, per-cycle cleanup re-establishes state, and the residual "timed-out macro still running" risk is accepted by design. CLI: `except NonRecoverableError → exit 1` renamed to `AbortRunError`; also fixed the clean-stop path — the outer loop now re-raises `AutofrapInterruptedException` after printing the "Grid stopped by user" summary, making the CLI's existing `exit 130` handler reachable (previously the outer loop swallowed the interrupt, so a clean stop exited 0).
